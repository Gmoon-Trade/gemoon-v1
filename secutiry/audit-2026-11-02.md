# Аудит безопасности gemoon-v1 (ветка `2.0`, коммит `318c978`)

Дата: 2026-11-02. Метод: ручной разбор исходников по чек-листу скилла `audit`
(переменные, функции, модификаторы, паттерны, внешние вызовы, события, SWC-100..136,
weird-ERC20, DeFi-проверки). Slither и `forge test` в этой сессии запустить не удалось
(см. раздел «Ограничения»).

Solidity 0.8.26, `via_ir`, EVM cancun. Целевая сеть: Robinhood Chain (chain id 4663,
Arbitrum Orbit), прод-деплой 2.0 от 2026-10-27 (свежий, не апгрейд).
Внешние зависимости: OZ 5.0.x (+upgradeable 5.0.2), Uniswap v4-core/periphery, v3-core,
Permit2, uniswap-hooks.

Модель доверия: владелец волта (Safe без таймлока) задаёт долю/получателя протокола,
allowlist активов, адаптер, паузу; владельцы ProxyAdmin могут заменить код контроллера,
волта и рефералов; владелец адаптера задаёт маршруты и допуск. Хук и TokenDeployer
без владельца. Непривилегированные: деплоер мема, трейдеры, стейкеры, создатель
(2-step передача роли), рефереры.

Не найдено.

## Высокие

Не найдено. Checks-effects-interactions соблюдён во всех денежных путях
(`HookManager._payout`, `Vault.notifyFees/convertFees/_stake/_unstake/_payReward`,

## Средние

### [M-01] Storage layout контроллера 2.0 несовместим с прокси до 2.0; README утверждает обратное
- Severity: Medium (High, если где-то живёт прокси контроллера старой версии и к нему применят `make upgrade-controller-proxy`)
- Location: `src/contracts/Gemoon.sol:78-99`, `script/GemoonDeploy.sol:1356-1380`, `README.md` («Мёртвый слот `_deployStrategies` … сохранён»)
- SWC: SWC-124 (запись/чтение чужих слотов через коллизию layout при апгрейде)
- Описание. В `main`/`dev`/`mainnet` слоты контроллера: `0 _wethInitialApproved(bool)`,
  `1 _deployStrategies(mapping)`, `2 _lpManager`, `3 _weth`. В 2.0 (по `storageLayout`
  из `out/`): `0 _weth`, `1 poolManager`, `2 hook`, `3 vault`, `4 positionManager`, …
  Комментарий «Appended in 2.0. Storage is append-only across upgrades» и пункт README
  про сохранённый мёртвый слот не соответствуют коду. При апгрейде старого прокси
  `hook` прочитается как адрес старого LPManager, `vault` — как адрес USDG, `_weth` —
  как `0x0`/`0x1`. `reinitialize` переписал бы `_weth` и `poolManager`, но он падает
  (`reinitializer(1)` после `initializer`, известная проблема), а `hook`/`vault`
  он не трогает.
- Impact. Сейчас прод-контроллер 2.0 развёрнут свежим, коллизии нет. Риск латентный:
  любой апгрейд legacy-прокси через `ProxyGemoonControllerUpgrade` либо упадёт целиком
  (с вызовом `reinitialize`), либо, если сделать `upgrade` без вызова, оставит контроллер
  с мусорными адресами и без возможности поправить `_weth` (сеттера нет:
  `setHook`/`setVault` будут падать на `HookPairTokenMismatch`/`VaultPairTokenMismatch`).
- Recommendation. Выбрать одно из двух и зафиксировать в README: (а) 2.0 — только
  свежий деплой: удалить `ProxyGemoonControllerUpgrade`/`upgrade-controller-proxy`
  и пункт про мёртвый слот; (б) поддержать апгрейд: вернуть четыре legacy-слота
  как `uint256 private __gap_legacy0..3` перед `_weth`… или, точнее, объявить
  `bool private _deprecatedWethApproved; mapping(string=>address) private _deprecatedDeployStrategies; address private _deprecatedLpManager;`
  перед `_weth`, поднять `GEMOON_VERSION` до 2, добавить тест апгрейда с layout
  старой версии (как `VaultUpgradeTest`) и проверку `forge inspect --storage` в CI.
  Неиспользуемый `poolManager` в слоте 1 при варианте (б) тоже надо переносить в конец.

### [M-02] Конвертация мема необратимо встаёт, если один из его наградных активов перестаёт свопаться; эскейп-хэтча у владельца нет
- Severity: Medium (ликвидность наград стейкеров и создателя)
- Location: `src/contracts/vault/Vault.sol:325-387` (`convertFees`), `:903-923` (`_swap`), `:219-254` (`registerVault`: список активов неизменяем)
- Описание. `convertFees` свопает весь USDG эпохи по всем активам одной транзакцией; любая
  ошибка в одном плече (`removeRoute`, `observe` → `OLD` при недостаточной cardinality,
  `PartialFill` при уходе ликвидности, `InsufficientOutput` при расхождении spot/TWAP,
  трансфер-ограничения токенизированных акций — blocklist/allowlist на волт) откатывает
  всю конвертацию. Список активов мема задаётся один раз в `registerVault`; владелец
  может менять только глобальный allowlist и маршруты адаптера, а allowlist на уже
  зарегистрированные мемы не влияет.
- Impact. `pendingStakerUSDG`/`pendingCreatorUSDG` мема копятся в волте без возможности
  выплаты: стейкеры и создатель не получают ничего, `claim` отдаёт только старые эпохи.
  Дополнительно каждый своп такого мема после `CONVERSION_COOLDOWN` (1 мин) сжигает
  до `conversionGasRequired` газа на заведомо падающей попытке (`_tryConvert`), а
  `NotEnoughGasForConversion` требует этот газ на каждом свопе. Починить можно только
  апгрейдом волта.
- Recommendation. Добавить owner-функцию миграции активов мема, ограниченную
  allowlist'ом (например, `replaceAsset(meme, index, newToken)` с сохранением весов,
  событием и запретом дубликатов) и/или деградацию: при падении плеча оставлять его
  долю в USDG (USDG — всегда допустимый «актив 0»). Покрыть fuzz/invariant-тестом:
  «после любой последовательности set/removeRoute сумма pending мема либо конвертируется,
  либо претендуема в USDG».

### [M-03] Публичный `convertFees` + допуск до 10 % от TWAP: MEV-извлечение до `maxSlippageBps` с каждой конвертации
- Severity: Medium
- Location: `src/contracts/adapters/UniswapV3SwapAdapter.sol:43` (`MAX_SLIPPAGE_BPS = 1000`), `:90-123`; `Vault.sol:325`, `:877-885`
- Описание. Защита цены — только TWAP (1 мин…1 ч) минус допуск маршрута. Момент конвертации
  предсказуем (порог виден ончейн, вызов публичный), объём — весь USDG эпохи. Сэндвич в
  пределах допуска проходит проверку `amountOut >= minOut`. На Orbit-сети мемпула нет,
  но секвенсер/бэкраннер в одном блоке и любой, кто сам вызывает `convertFees` после
  собственного свопа в V3-пуле, извлекают до `maxSlippageBps` объёма. Короткое окно TWAP
  (1 мин) в неликвидном пуле сдвигается одной сделкой.
- Recommendation. Для ликвидных маршрутов ставить допуск 50–200 bps, окно ≥ 30 мин;
  ограничить верхнюю границу `MAX_SLIPPAGE_BPS` до 300–500; рассмотреть порог
  конвертации, при котором объём не превышает долю ликвидности пула (или дробление
  конвертации). Зафиксировать в README рекомендуемые параметры на актив.

### [M-04] Централизация: доля протокола 0..100 % меняется мгновенно, прокси волта без таймлока
- Severity: Medium (доверие)
- Location: `Vault.sol:541-545` (`setProtocolShare` до `BPS`), `:534-538` (`setProtocolRecipient`), ProxyAdmin волта/контроллера/рефералов
- Описание. Владелец волта одним вызовом переводит 100 % всех будущих комиссий на любой
  адрес; `FeeInfo` в токене — лишь снимок на момент деплоя. Владелец ProxyAdmin волта
  может заменить код контракта, в котором лежат все стейки и неразданные награды.
  README честно описывает Safe без таймлока.
- Recommendation. Ограничить `setProtocolShare` константой (например ≤ 5 000 bps),
  поставить TimelockController владельцем ProxyAdmin'ов волта и контроллера (24–48 ч),
  описать это в README как гарантию для стейкеров.

## Низкие / информационные

### [L-01] У реализации `GemoonController` нет `_disableInitializers()` в конструкторе
- Location: `Gemoon.sol:43` (конструктора нет; в `Vault`/`GmoonReferrals` он есть)
- `initialize` реализации может вызвать кто угодно. Для Transparent-прокси вреда нет
  (нет delegatecall/selfdestruct), но это отклонение от паттерна OZ и от двух других
  контрактов. Добавить конструктор с `_disableInitializers()`.

### [L-02] `withdraw` через `transfer` (SWC-134), `withdrawERC20` без проверки возврата (SWC-104)
- Location: `Gemoon.sol:523-525`, `:531-545`
- `payable(recipient).transfer` ломается на получателях-контрактах с дорогим `receive`
  (Safe). `erc20.transfer(to, amount)` игнорирует `bool` — для USDT-подобных токенов
  молча «успех». Использовать `Address.sendValue` и `SafeERC20.safeTransfer`.

### [L-03] `deployToken` объявлен `payable`, `msg.value` не используется
- Location: `Gemoon.sol:218-220`
- Случайно присланный ETH оседает на контроллере (достаётся владельцу через `withdraw`).
  Убрать `payable` или `require(msg.value == 0)`.

### [L-04] Плавающие прагмы и отсутствующие SPDX (SWC-103)
- `^0.8.20/21/26` во всех контрактах, кроме `TokenDeployer` и `ProjectToken`;
  `utils/Ticks.sol`, `utils/TimeMath.sol` без SPDX. CLAUDE.md требует явные версии в проде.
  Зафиксировать `pragma solidity 0.8.26;`.

### [L-05] Документация расходится с кодом по анти-снайп окну и админам мема
- `HookManager.DYNAMIC_FEE_THRESHOLD = 10 seconds` (`HookManager.sol:72`), README говорит
  «первые 15 секунд» (таблица контрактов) и «`DYNAMIC_FEE_THRESHOLD` секунд (30)»
  (жизненный цикл), FEES.md — 15 секунд. NatSpec `deployToken` и README-ABI обещают
  копирование `tokenConfig.admins` (известный tech debt, но NatSpec не поправлен).
  Обновить README/FEES/README-ABI.

### [L-06] `Admin.replaceAdmin` молча ничего не делает, если `oldAdmin` не найден, и допускает дубликаты
- Location: `utils/Admin.sol:19-37`; `Gemoon.sol:507-514`
- `changeAdmin` возвращает успех без изменений; `newAdmin` может уже быть админом.
  Добавить `revert AdminNotFound()` и проверку дубликата. Сейчас не эксплуатируемо:
  все админы non-removable.

### [L-07] `claimCreatorRewards` — «всё или ничего» по активам
- Location: `Vault.sol:473-488`
- Один актив с трансфер-ограничением на адрес создателя (blocklist токенизированной
  акции) блокирует выплату всех остальных активов создателю до смены роли через
  `transferCreator/acceptCreator`. У стейкеров есть выборочный `claim(meme, assets)`,
  у создателя — нет. Добавить вариант с выбором активов.

### [L-08] Пыль округления в волте заперта навсегда
- Location: `Vault.sol:299-322`, `:816-869`
- Сумма кредитов стейкеров ≤ `pendingStakerUSDG` (mulDiv вниз), остаток активов
  попадает в `s_accounted`, поэтому `rescueERC20` его не видит. Величина — доли wei на
  эпоху, но за годы и сотни мемов копится. Информационно; можно учитывать
  невостребованный остаток эпохи и отдавать протоколу/создателю.

### [I-01] Комиссию можно обойти торговлей вне хукового пула
- Токен без трансфер-ограничений: любой может поднять пул Meme/USDG без хука (V4 с другим
  хуком, V2/V3) и торговать без комиссии; роутеры предпочтут дешёвый путь. Это дизайн-
  ограничение, адресуется планом URC-5 (`docs/URC5-PLAN.md`). Зафиксировать в README как
  известное ограничение, если ещё нет.

### [I-02] Каждый своп мема с включённой автоконвертацией требует до ~3,3 М газа
- `_payoutGas` требует `conversionGasRequired` на каждом свопе, а не только пересекающем
  порог; роутеры с фиксированным лимитом газа на хоп будут падать с
  `NotEnoughGasForConversion`. Задокументировано, но стоит сообщить интеграторам.

### [I-03] `require` со строками вместо кастомных ошибок
- `Gemoon.sol` (`_init`, `_configurePool`, `_validateTokenConfig`, `withdrawERC20`),
  `utils/Admin.sol`, `utils/Price.sol`, `utils/TimeMath.sol`, `Token.sol:111`.
  Конвенция CLAUDE.md — кастомные ошибки.

### [I-04] Первая выплата комиссии после создания пула падает (известно)
- Роутер переводит USDG после `afterSwap`; `take` в `_payout` откатывается в try/catch.
  Описано в README, поведение безопасно.

## Проверено, проблем нет (ключевые точки)

- Хук: `beforeSwapReturnDelta`/`afterSwapReturnDelta` + `poolManager.mint` на себя —
  стандартный паттерн, дельты хука сходятся в ноль; `HookDeltaExceedsSwapAmount`
  недостижим (макс. 80 % < 100 %); `_afterInitialize` берёт `sender` из PoolManager,
  подделать нельзя; `notifyPoolCreated` только в блоке создания и один раз.
- Dev buy: `unlockCallback` достижим только через собственный `unlock`; слippage
  `maxPairIn` проверяется; `take` мема и `settle` USDG в одной транзакции.
- Волт: учёт по эпохам (S, X_e, A_e,i, K_e,i) проверен на согласованность; пересчёт
  стейкера O(активов), без циклов по эпохам; `stake` по разнице баланса; `unstake`
  работает на паузе; `rescueERC20` ограничен излишком над `s_accounted`.
- Адаптер: пул только из фабрики; колбэк принимает только пул маршрута и только во
  время собственного свопа; `PartialFill` и `InsufficientOutput` откатывают своп.
- Рефералы: инвариант `balance ≥ totalPending` проверяется при каждом начислении,
  пауза не трогает начисление и вывод протокола.
- Токен: счётчик холдеров корректен для mint/transfer/burn/self-transfer/нуля;
  JSON-экранирование метаданных; `ERC20Permit` с именем токена.
- PositionDeployer: Permit2-аллованс с `expiration = block.timestamp` валиден
  (проверка `block.timestamp > expiration`), остаток аллованса не остаётся.
- Weird-ERC20: USDG и наградные активы — allowlist владельца; USDT-подобные покрыты
  SafeERC20; fee-on-transfer/rebasing для наград сломали бы учёт `s_accounted` —
  не добавлять такие активы в allowlist (зафиксировать в README).

### [L-09] Dev buy не сверяет результат `settle()` с `pairIn`
- Location: `Gemoon.sol:497`
- `poolManager.settle()` возвращает фактически зачисленную сумму. Сейчас корректность держится
  на том, что PoolManager сам откатит транзакцию при ненулевой дельте; явная проверка
  `if (poolManager.settle() != pairIn) revert` дешевле в диагностике и защищает от
  pair-токена с комиссией на перевод. Hardening, не уязвимость.
